# Oculus Go Air Mouse

.NET 10 WPF 桌面程序，使用 WPF 内置 Fluent 主题（跟随 Windows 明暗模式）。原 Python 项目保持不变。

## 构建与启动

需要 Windows 10 2004 或更高版本、蓝牙适配器以及 .NET 10 SDK。用 Visual Studio 打开 `OculusGoAirMouse.slnx`，或在本目录运行：

```powershell
dotnet build
dotnet run --project OculusGoAirMouse.csproj
```

编译后的程序：`bin\Debug\net10.0-windows10.0.19041.0\OculusGoAirMouse.exe`。

## 使用

1. 在 Windows 蓝牙设置中配对 Oculus Go 控制器，退出旧 Python 程序。
2. 按 Trigger 唤醒后点击“搜索并连接”。界面显示连接阶段和等待时间；可点击“断开 / 取消”。
3. 保持静止完成 250 样本校准，再点击“开启鼠标”。
4. Oculus 回主屏中心；Trigger 左键和拖拽；Back 右键；触摸板上下、左右整格滚动。
5. 设置页面支持手动修改、校验和保存。保存后暂停控制并重新校准，蓝牙名称和超时在下次连接时使用。

默认参数从迁移时的 Python 文件读取：X/Y 灵敏度 1.75/1.25，死区 65，轴 0/2，X 反转开、Y 关，光标平滑 0.8，最大位移 100，校准 250，按键超时 3 秒，滚动阈值 30，垂直滚动不反转、水平滚动反转。

默认配置为 `settings.default.json`；个人配置位于 `%LOCALAPPDATA%\OculusGoAirMouse\settings.json`。首次启动生成个人配置，保存采用临时文件替换。配置损坏时显示错误并暂用默认值，原文件不会在加载失败时被覆盖。

断线、超时、关闭鼠标和退出时释放模拟鼠标按键。程序以普通用户权限运行，无法控制权限更高的窗口。水平滚动是否生效取决于目标应用。本版本不自动重连，不包含开机启动和托盘功能。

控制器数据解析、鼠标输入和按键超时保护在独立输入线程串行处理，不依赖 WPF 界面线程。界面只读取状态快照，避免标题栏最大化、最小化或移动窗口时延迟发送松键事件。断开和退出会停止接收数据、丢弃旧帧并释放按键；输入积压超过保护阈值时停止控制并提示重新连接。

回归检查：`dotnet run --project tests/OculusGoAirMouse.Checks.csproj`。包括暂停调用线程时仍发送松键、独立超时释放、停止后丢弃数据等检查。

0.2.0 标题栏兼容处理：控制器点击本程序的最小化、最大化/还原、关闭按钮时，不注入原生标题栏按下事件；松开且仍位于同一按钮时通过异步 WM_SYSCOMMAND 执行操作。移出按钮或超时、断线时取消操作。此处理仅针对本程序主窗口，系统鼠标和其他窗口不受影响。连接日志会记录对应的窗口命令，便于硬件复测。独立线程修改本身不足以证实已解决硬件场景，本版本仍需控制器验收。

0.2.1：增加 WM_GETTITLEBARINFOEX 提供的系统按钮区域快照，避免只依赖 WM_NCHITTEST 漏掉最小化按钮。窗口移动、缩放、DPI 和状态变化时由界面线程更新区域，输入线程直接读取。短时输入诊断保存于 `%LOCALAPPDATA%\OculusGoAirMouse\input-diagnostics.log`，每次启动重新生成，记录控制器按钮变化、接收/处理计数、标题栏识别和窗口状态；不记录原始传感器数据或桌面操作内容。

0.2.2：显式创建并保持 GATT 会话（MaintainConnection），窗口最小化不会主动释放会话。Windows 报告链路中断时立即停止鼠标并释放按键，保留会话等待 3 秒；期间恢复则重新校准，需用户重新开启鼠标；持续中断才确认断线并清理。主动断开或退出会取消掉线检查并释放会话，不后台无限重连。诊断记录新增蓝牙状态、GATT 状态及错误、输入错误和清理原因；仅靠现有记录尚不能确认间歇断线的硬件或系统原因。

蓝牙实际连接、控制器通知和鼠标手感需要连接硬件验收。Windows 蓝牙服务读取可能较慢，超时取消涉及系统操作完成和资源清理，不保证严格按秒结束。
