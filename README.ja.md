# Oculus Go Air Mouse

[English](README.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md)

Oculus Go コントローラーを Windows のエアマウスとして使用するデスクトップアプリです。現在のバージョンは **0.5.1**。**.NET 10、WPF Fluent Theme、CommunityToolkit.Mvvm 8.4.2** を使用し、MVVM 構成を採用しています。画面の明暗テーマはシステム設定に従います。

![Oculus Go コントローラー](https://s3files.core77.com/blog/images/922267_90183_87578_86lxkpMhC.jpg)

上の画像は、このプロジェクトが対応する Oculus Go コントローラーです。

## 動作環境

- 十分な電池残量のある Oculus Go コントローラー、Bluetooth LE（BLE）対応アダプター、および正常に動作するドライバー。
- .NET 10 に対応した Windows デスクトップ環境。Windows 11 を推奨します。プロジェクトのターゲットは `net10.0-windows10.0.19041.0` です。ターゲット API のバージョンは、該当するすべての Windows リリースが現在の .NET でサポートされることを意味しません。[Microsoft の Windows/.NET 動作要件](https://learn.microsoft.com/en-us/dotnet/core/install/windows)を確認してください。
- 通常のビルドまたはフレームワーク依存の配布版には **.NET 10 Desktop Runtime** が必要です。基本の .NET Runtime だけでは不足します。ソースのビルドには .NET 10 SDK が必要ですが、配布版の実行に Visual Studio は不要です。
- 実行ファイルは `requireAdministrator` により管理者権限を要求します。通常のデスクトップ上で、タスクマネージャーなど管理者権限のウィンドウを操作するためです。UAC が表示されたら承認してください。キャンセルすると起動しません。既に昇格済みの環境では、再確認されない場合があります。

## 初めて使う場合・別の PC で使う場合

> **アプリを使う前に、Windows で Bluetooth ペアリングを完了してください。このアプリは検索と接続を行いますが、システムのペアリングは行いません。「検出済み」と「ペアリング済み」は異なります。PC ごとにペアリングが必要です。**

1. コントローラーをペアリングモードにします。**Windows 設定 → Bluetooth とデバイス → デバイスの追加 → Bluetooth** を開き、コントローラーを選んでペアリングを完了してください。
2. 同時接続を避けるため、他の PC のコントローラーアプリを終了してください。必要に応じて、他の PC の Bluetooth を一時的にオフにします。
3. `OculusGoAirMouse.exe` を起動して管理者権限の要求を承認し、**Trigger** を押してコントローラーのスリープを解除します。
4. 既定では、自動で検索・接続し、接続後にマウス操作を有効化します。未ペアリングのため停止した場合は、ペアリング完了後に **検索して接続** をクリックしてください。
5. 自動キャリブレーションは既定で無効です。未調整のままでも使用できます。静止時にカーソルが動く場合は、**再キャリブレーション** をクリックするか **Oculus を 1 秒間長押し**し、その後コントローラーを動かさないでください。

検索では、Bluetooth のブロードキャスト名と `DeviceName` を、大文字・小文字を区別して完全一致で照合します。既定値は `OMVR-V190` です。検出した Bluetooth アドレスに接続し、必要なサービスと特性の UUID を確認します。特定の PC のアドレスには固定されていません。同じ名前のコントローラーが複数あると、最初に見つかったものが選ばれる場合があります。

## 表示言語

上部の **Language / 语言 / 言語** メニューで **English**、**中文**、**日本語**、**システムに合わせる** を選択できます。既定の `"Language": "system"` では、現在の Windows ユーザーのシステム表示言語に合わせます。中国語は中国語、英語は英語、日本語は日本語になり、対応していない言語は英語にフォールバックします。

手動で選択すると、ボタン、タブ、使い方、設定ラベル、状態、およびアプリが生成する接続ログが即座に切り替わります。選択は現在のユーザーの `settings.json` に自動保存され、次回起動時にも使用されます。「システムに合わせる」で自動選択に戻せます。切り替えても再接続、再調整、未保存の設定の適用は行わず、数値入力の地域形式も変更しません。Windows やドライバーの元のエラーはシステム言語のままの場合があります。ディスク上の診断ログは調査用の原文を保持します。

## 操作方法

| 操作 | 動作 |
| --- | --- |
| コントローラーを回転 | カーソルを移動 |
| Oculus を押す | メイン画面の中央へ即座に移動 |
| Oculus を 1 秒間長押し | 離さずに再調整を開始。1 回の長押しにつき 1 回だけ実行 |
| Trigger | 左クリック。押したままでドラッグ |
| Back | 右クリック |
| タッチパッドを上下 / 左右にスライド | 縦 / 横スクロール（ノッチ単位）。横スクロールの対応は対象アプリによる |
| 切断 / キャンセル | 接続処理をキャンセルするか切断し、仮想マウスボタンを解放 |
| ウィンドウを閉じる | 操作を停止し、バックグラウンドのリソースを解放 |

Oculus の長押しでは、まず押した瞬間に中央へ移動し、1 秒に達すると調整を開始します。離したときに追加の操作は行いません。

### キャリブレーションと進捗リング

- `CalibrationDurationSeconds` で調整時間を **0.1–3 秒**に設定できます。既定値は **1.25 秒**です。長押し判定の固定時間である 1 秒とは別の設定です。
- 有効なジャイロデータから計測を開始します。データが 0.25 秒を超えて途切れた場合は、計測をやり直します。
- 調整中は仮想ボタンを解放し、移動とクリックを停止しますが、マウスの有効・無効状態は保持します。完了後、元が有効なら再開し、無効ならそのままです。調整中に手動で無効化した場合も再び有効にはしません。
- 青い円形の進捗リングがカーソルに追従します。最前面に表示され、クリックを透過し、フォーカスを奪いません。メインウィンドウを最小化していても表示されます。完了、切断、終了時に非表示または解放されます。
- 通常のアプリウィンドウを覆いますが、セキュアデスクトップ、排他的フルスクリーンなどの特殊な表示層を覆うことは保証しません。
- 自動調整が無効の場合、未調整の入力ではバイアスをゼロとして扱います。同じアプリ実行中の再接続では完了済みの調整結果を再利用できます。結果はアプリの再起動をまたいで保存されません。

### クリック時の手ぶれ対策

Trigger / Back を押した後と離した後に、それぞれ一定時間ジャイロによるカーソル移動を固定します。ボタン操作は即座に送信されます。押したままでも固定時間が終わればドラッグできます。スクロールと物理マウスはこの固定の影響を受けません。

固定中の移動量は破棄し、平滑化の残りも消去するため、解除後にカーソルが飛ぶのを防ぎます。固定は押下・解放データを受信した時点から始まり、押す前の動きを予測したり巻き戻したりはしません。2 つの時間を個別に設定でき、`0` で対応する固定を無効にできます。

## 設定とユーザーデータ

**設定** タブで編集し、**保存して適用** をクリックします。保存前に値の範囲を検証します。保存後はマウス操作が一時停止するため、必要に応じて再び有効化してください。自動再調整は `AutoCalibrateOnConnect` に従います。起動時の動作は次回起動時から、デバイス名とタイムアウトはその後の接続処理から適用されます。

| ファイル | 用途 |
| --- | --- |
| 実行ファイルと同じ場所の `settings.default.json` | 個人設定がない場合に読み込む既定値 |
| `UserData\<ユーザー名>\settings.json` | 現在の Windows ユーザーの設定。優先して読み込む |
| `UserData\<ユーザー名>\input-diagnostics.log` | 実行時の診断ログ。起動時に作り直す |

既定値ファイルを変更しても、既存の個人設定は上書きしません。個人設定がない場合は作成します。読み込みエラー時は通知してモデルの既定値を使用し、破損ファイルを自動では上書きしません。保存には一時ファイルからの置換を使用します。データの基準は実行ファイルのディレクトリ（`AppContext.BaseDirectory`）で、ショートカットの作業フォルダーではありません。ユーザー `jinge` の例：

```text
OculusGoAirMouse.exe
settings.default.json
UserData/
  jinge/
    settings.json
    input-diagnostics.log
```

サブフォルダー名には、実行中のプロセスの Windows ユーザー名を使用します。別の管理者アカウントで起動すると、そのユーザー名になります。必要なフォルダーは自動作成します。実行アカウントにはアプリのディレクトリへの書き込み権限が必要です。

新しい場所に `settings.json` がない場合、旧保存先の `%LOCALAPPDATA%\OculusGoAirMouse\settings.json` を検証して移行します。旧ファイルは残します。新しい設定が既にある場合はそちらを優先します。旧ファイルが破損していればエラーを表示し、自動では上書きしません。過去のログは旧保存先に残り、新しいログは新しい場所に保存します。

アプリのディレクトリごとに `UserData` が存在します。アプリを移動したり、別の発行先を使ったりする場合は、必要なユーザーのサブフォルダーもコピーしてください。公開する配布パッケージやソース管理には `UserData` を含めないでください。

以下は、リポジトリ内の現在の `settings.default.json` と一致する値です。

| 設定項目 | 既定値ファイルの値 | 説明 / 範囲 |
| --- | --- | --- |

## 接続・スリープ・デスクトップの復旧

- 起動時または手動接続に失敗するとセッションを解放し、**2 秒**後に再試行します。最大 **3 回の試行**です。未ペアリングの場合はユーザーによる対応が必要なため、その時点で再試行を停止して手順を表示します。ペアリング後に手動で接続してください。
- 一時的な Bluetooth 中断では入力を停止してボタンを解放し、約 **3 秒**セッションを保持します。中断が続き、`AutoReconnect=true` の場合は再検索を繰り返し、失敗するたびに 2 秒待ちます。手動切断、自動再接続の無効化、終了で再試行を停止します。
- 再接続後は、切断前のマウス有効・無効状態に戻ります。再調整するかどうかは `AutoCalibrateOnConnect` に従います。すべての通知登録が完了するまでコントローラー入力は処理しません。
- PC のスリープ時は接続処理をキャンセルし、ボタンを解放します。復帰後は **2 秒**待ちます。スリープ前に接続済み、接続中、または再接続中で、自動再接続が有効なら、接続と元のマウス状態の復旧を試みます。コントローラー自体がスリープしている場合は、Trigger による解除が必要なことがあります。
- ロック画面や一時的に入力できないセキュアデスクトップでは、接続とマウスのスイッチ状態を保持して出力を停止します。デスクトップ復旧後は古い入力を破棄し、必要なボタン解放を送信します。押したままのボタンを離してから新たな押下を受け付け、誤クリックを防ぎます。
- 通常のデスクトップで継続する入力権限エラーは、引き続き障害として通知します。管理者権限でも、UAC のセキュアデスクトップ、ロック画面、すべての保護されたウィンドウを操作できるわけではありません。

## CPU 優先度

マウス入力スレッドは `AboveNormal` で動作します。バックグラウンドで毎秒 CPU 負荷を計測し、接続済みでマウス操作が有効な場合に調整します。

- **80% 以上**が 2 回連続すると、このプロセスの通常またはそれ以下の優先度を `AboveNormal` に上げます。
- **60% 以下**が 5 回連続するか、マウス操作を無効化するか、接続を切ると、元のプロセス優先度に戻します。
- 起動環境が元から指定していた高い優先度は保持します。アプリから `High` や `RealTime` には設定しません。

監視に失敗しても Bluetooth 接続は停止しません。変更とエラーはログに記録します。終了時に監視を止め、元の優先度に戻します。優先度の調整は実行機会を改善しますが、CPU 飽和、ドライバー遅延、Bluetooth 干渉によるカクつきを完全になくす保証はありません。

## ビルドと起動

プロジェクトのルートで実行します。

```powershell
dotnet build OculusGoAirMouse.slnx
```

以下の実行ファイルをダブルクリックし、UAC を承認してください。

```text
bin\Debug\net10.0-windows10.0.19041.0\OculusGoAirMouse.exe
```

PowerShell から起動する場合：

```powershell
Start-Process -FilePath '.\bin\Debug\net10.0-windows10.0.19041.0\OculusGoAirMouse.exe' -Verb RunAs
```

Visual Studio でデバッグする場合は、Visual Studio を管理者として起動し、`OculusGoAirMouse.slnx` を開いてください。ビルドを更新する前に実行中のアプリを閉じ、出力ファイルのロックを解除してください。

## 別の PC 向けに発行

以下は **Windows x64** 向けの例です。Arm64 / x86 の PC では、対応するランタイム識別子を使用してください。どちらの方式でも、`settings.default.json` を含めて出力フォルダー全体をコピーします。

フレームワーク依存版。実行先に .NET 10 Desktop Runtime が必要です。

```powershell
dotnet publish OculusGoAirMouse.csproj -c Release -r win-x64 --self-contained false -o .\bin\publish\win-x64-framework
```

自己完結型。実行先で .NET を別途インストールする必要はありません。

```powershell
dotnet publish OculusGoAirMouse.csproj -c Release -r win-x64 --self-contained true -o .\bin\publish\win-x64-selfcontained
```

[Microsoft の発行ガイド](https://learn.microsoft.com/en-us/dotnet/core/deploying/)も参照してください。自己完結型でも、Windows の互換性、Bluetooth ドライバー、管理者権限、システムのペアリングは必要です。

新しい PC でペアリングを完了してから `.exe` を実行します。個人設定を移す場合は、元のアプリフォルダーの `UserData\<元のユーザー名>\settings.json` を、新しいアプリフォルダーの `UserData\<新しいユーザー名>\settings.json` にコピーしてください。ペアリング情報や調整結果は設定ファイルと一緒には移りません。

## よくある問題と診断

| 症状 | 確認すること |
| --- | --- |
| コントローラーが見つからない | 電池、Bluetooth、ブロードキャスト名、Trigger による復帰、他の PC の接続を確認 |
| 見つかるが未ペアリングと表示される | この PC の Windows Bluetooth 設定でペアリングしてから手動接続 |
| `0x8065000F` / 暗号化不足 | この PC のペアリングを確認。ペアリング済みなら削除して再ペアリング |
| `AccessDenied` / サービスへのアクセス拒否 | ペアリング状態、サービスのアクセス状態、診断ログ、他の接続、ドライバーを確認。この状態だけでは原因を断定できない |
| 3 回とも接続に失敗 | 接続ログと診断ファイルを確認し、エラーコードと `connect attempt=` 付近のスタックトレースを保存 |
| タスクマネージャーなどを操作できない | 現在の `.exe` を起動して管理者権限を承認したか確認。UAC のセキュアデスクトップは操作対象外 |
| 静止時にカーソルが流れる | 再調整し、デッドゾーン、感度、コントローラーの安定性を確認 |
| クリック時にカーソルが飛ぶ | 押下後・解放後の固定時間を調整し、静止時にも流れがあるか確認 |
| スリープ復帰後に回復しない | デスクトップをロック解除し、Trigger でコントローラーを起こす。自動再接続設定と電源・入力デスクトップの診断を確認 |

問題が起きたら、次回起動で上書きされる前に診断ログを保存してください。報告にはアプリのバージョン、Windows バージョン、Bluetooth アダプターとドライバー、再現手順、該当ログを含めてください。回帰テストのログはテスト出力内の `scratch` に分離され、実行時の診断ログを上書きしません。

## 検証と開発構成

実機コントローラー不要の回帰チェック：

```powershell
dotnet run --project tests/OculusGoAirMouse.Checks.csproj
```

ネイティブの進捗リングチェックは、コントローラーに接続せず短時間テストウィンドウを表示します。同じ管理者マニフェストを使用するため、昇格済みのターミナルから実行してください。

```powershell
dotnet run --project tests/OverlaySmoke/OverlaySmoke.csproj
```

英語・中国語・日本語の UI チェックは模擬ランタイムを使用し、コントローラーに接続せず、実際の個人設定にも書き込みません。

```powershell
dotnet run --project tests/LanguageSmoke/LanguageSmoke.csproj
```

システム言語のフォールバック、言語切り替えと保存、設定検証、未ペアリングエラー、入力、クリック固定、調整、スクロール、独立入力スレッド、タイトルバー互換処理、切断・スリープ復旧、入力できないデスクトップ、優先度調整、リソース解放を検証します。実際の Bluetooth 互換性、スリープ動作、高負荷時の操作感は実機テストが必要です。

```text
Models/        設定と範囲の検証
ViewModels/    UI 状態、非同期コマンド、設定編集と保存
Services/      Bluetooth、入力スレッド、マウス出力、進捗リング、CPU 調整、設定とログ
MainWindow.*   バインディング、タイトルバー座標、ログスクロール、終了処理
App.xaml.cs    サービスの構成、電源イベント、終了時の解放
tests/         回帰チェックとネイティブウィンドウのチェック
```

ViewModel は CommunityToolkit.Mvvm の `ObservableObject`、`ObservableProperty`、`RelayCommand` を使い、ランタイム、設定ストア、UI スケジューラーのインターフェイスに依存します。コントローラー入力は独立したスレッドで直列に処理し、マウスボタンの解放は UI スレッドに依存しません。

正常終了では、接続・再接続処理のキャンセルと待機、仮想ボタンの解放、Bluetooth イベントの購読解除、通知とセッションの終了、入力スレッドと UI タイマーの停止、電源イベントの購読解除、進捗リングの終了、優先度監視の停止、ログの書き出しとクローズを行います。プロセスの強制終了では、すべての終了処理は実行されません。

Git でソース履歴を管理します。`bin/`、`obj/`、Visual Studio キャッシュ、ログ、`UserData/`、バックアップは `.gitignore` で除外します。
